# 新根落子次序专项：评测协议

当前路线图处于第3步落子次序专项；本轮先准备新数据，只有数据门槛通过才启动固定训练。通过本协议的策略开发门槛，也只允许准备后续搜索验证，不能直接晋升冠军或宣称整局棋力提高。

## 具体判断

同一真实合法根上比较两个已冻结几何候选：后排接力一步与前锋现成长跳，学习其相对先后次序。角色rear/front是候选几何身份，不预设后排一定更好。

48个根先按预定几何规则生成，32训练、16开发；先固定全部schedule及哈希，再查询标签。不按NN错误选根，不按教师分数重新补根，不为了凑双向样本不断追加候选。完整对称轨道与历史隔离按项目规则执行；旋转换色轨道仅用于保守排除，不擅自做不符合先手规则的胜负增强。

## 标签和样本门槛

每根保存两候选在固定depth4和depth5配置下的相对分数。只有两深度差值同号、均非零、且depth5绝对差至少2才eligible。标签为+1（rear相对优）或−1（front相对优）。其他根保留原记录和不适用原因，不被覆盖或丢弃后补。

eligible少于训练16/开发8，或任一方向少于训练4/开发2，均不启动训练。数据不通过就结束本轮，不把弱覆盖改称成功。

prepare_rows逐根重放冻结opening核对board/player/ply，保留实际重复历史；验证两path合法、起终点不同、depth4/5标签一致。由合法端点集合及canonical action_id生成x/actions。只给策略相对监督，value_weight=0；教师搜索分数不是胜负标签。

## 主要策略指标

定义同根logit差g=logit(rear)−logit(front)，标签y=sign(score5_rear−score5_front)。

- 排序准确：y×g严格大于0。logit完全同分算未辨明，不算正确。
- rear优/front优分别报告例数和准确率。
- balanced accuracy为两方向准确率的等权平均；缺任一方向时为null，不把另一个方向的高准确率冒充平衡表现。
- pair CE为softplus(−y×g)，用数值稳定实现，不受完整动作数不同影响。
- pair score regret：排对计0，排错或logit tie计abs(depth5两候选分差)。这是“未判对这两招的分差惩罚”，不是NN实际全合法动作的损失，也不是预期胜率损失。
- 同时报告全部合法动作argmax是否落在rear/front中、是否等于两招中教师较优者。这只是辅助统计，不把pair排序正确等价为NN真正会选择那招。实际argmax不在两者时，没有补查询其教师分数，也不给它编造质量分。

另外保留逐例两logit、带方向margin、teacher gap和选择，按P1/P2分层。评测统一eval与冻结requires_grad状态，再恢复原状态，避免CPU数值路径差异。

## 固定训练与评测时机

数据质量通过后，使用预声明的同v3、固定2000更新和优化器预算。开发不进入损失、采样或任何中途选择。v3开发基线一次，最终2000步候选一次，不对中途检查点试开发，不选择开发最优训练步。

价值头参数哈希必须保持，作为工程检查。但共享CNN更新仍能改变价值输出，因此另报旧价值MSE；不得把参数冻结写成价值输出冻结。

## 开发通过门槛

下列条件必须全部满足，使用未四舍五入的数值：

1. 开发eligible不少于8，rear优/front优各不少于2。
2. 开发balanced accuracy至少0.75，且比原v3至少提高0.125。
3. rear优与front优准确率分别至少0.60。
4. 开发pair CE不高于v3，pair score regret平均不高于v3。
5. 旧653策略CE、旧653价值MSE、普通353策略CE各不超过v3对应值+0.05。
6. 冻结价值参数哈希不变。

order_gate实现第1—4项，runner独立合并第5—6项。通过仅为相对判断开发通过，不是全合法策略最优或独立实战通过。失败不在这16根上调学习率、补步数、换门槛重考。

## 证据边界

depth4/5同号提高了局部标签一致性，但两候选都可能不是该局面最佳着法，也可能在不同续弈策略下优劣改变。相对分数不是真实胜率、终局结果或人类高手定论。训练监督应称“固定深度派生专家对几何候选的相对排序”，不是原Clysto完整最优标签，更不是纯自对弈。

本轮开发集合小，具有同一几何模板的采样偏向。它适合检验是否学会一项狭窄判断；即使通过，还要检验其能否转成NN/MCTS实际选择，再以全新隔离开局做独立整局确认。当前冠军保持原样。
