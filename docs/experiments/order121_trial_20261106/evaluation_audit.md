# 落子次序专项：独立评测审计

当前路线图：步骤3的落子次序专项。本轮在训练前数据覆盖门槛处停止，未进入模型训练或开发模型评测，不晋升。

本审计只读实际48根的冻结数据、标签、schedule哈希、流水线状态和runner代码；未调用NN、教师搜索或对局。独立重算每根depth4/5分差、eligible及方向，全部与原数据一致。

## 覆盖门槛

|划分|生成根|eligible|后排优|前锋优|要求|
|---|---:|---:|---:|---:|---|
|训练|32|24|8|16|总数至少16、两方向各至少4：通过|
|开发|16|9|1|8|总数至少8通过，但后排优至少2失败|

数据不是全部“前锋优”：训练已有8个后排优，开发已有1个，但不足以检验两方向都学会。若只教“永远选前锋”，在9个eligible开发根上微平均准确率就有8/9=88.9%，balanced accuracy却只有50%。这正是必须保留双方向覆盖和balanced门槛的原因，不能为了开训删掉这道检查。

|划分/走棋方|eligible|后排优|前锋优|

## 不适用标签分解

先按depth4平分、depth5平分、方向翻转、depth5差不足2顺序给互斥原因：

|原因|训练|开发|
|---|---:|---:|
|depth4平分|2|1|
|depth5平分|0|1|
|depth4/5方向翻转|1|3|
|同方向但depth5差小于2|5|2|
|eligible|24|9|

不能把平分改成任一方向，不能丢弃翻转后补新根凑数量，也不能把depth5差1临时放宽为可训练。48根schedule哈希与采集前freeze记录一致，split与根数没有为结果重排。

## Runner评测逻辑审查

若数据通过，runner才会调用prepare_rows、冻结v3开发基线、训练固定2000次，并在最终检查点评开发一次；每400次只看train。order_gate合并balanced准确率、相对增益、两方向、pair CE和pair分差惩罚，runner再合并旧653策略/价值及普通353策略保护、冻结价值参数哈希，符合协议。

评测统一eval与requires_grad状态，结束恢复参数flags。value参数冻结不等于共享CNN下的value输出冻结，runner另测旧valueMSE。

本轮数据未过，完整路径并未执行：没有baseline.json/final.json，也没有候选检查点。当前冠军检查点和注册表SHA与运行前config逐值一致。因此balanced accuracy、pair CE、pair regret、实际all-legal argmax命中率及候选模型门槛均应记“不适用/未运行”，不能借用旧模型实验数字填表。机器审计中相应字段明确为null。

代码说明有一处文字小偏差：采样描述写“16个有效train组”，但实际实现从全部eligible train组均匀抽取每批16根。此次未采样，不影响结果；主线程将作运行后文字修正为“每批16根，从所有eligible train组均匀抽”，原运行配置与源码快照保持不变；不是改采样算法或重跑。

## 结论与后续

本轮成功完成一次诚实的覆盖检查，并发现当前几何采样模板不足以稳定提供双向开发证据；它不是一次NN训练失败，因为训练没有开始。

保留48根及全部未适用标签，结束当前配置，不追加根、不重分开发、不把开发1个正例复制成2个。可先只读比较已有训练根的几何条件与标签，明确哪些后排短步有即时接力入口、哪些只是把后排向前挪一格；未来若需新采样，必须作为新实验先声明几何分层、规模和split，再冻结全新schedule，不能根据标签逐个补到成功。

候选动作的depth4/5分差仍是固定派生专家的局部相对评价，不是实际胜率或全局最优着法。当前冠军和GUI保持原样。
