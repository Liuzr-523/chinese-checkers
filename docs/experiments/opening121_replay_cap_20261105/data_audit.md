# 独立数据审查

固定32个开局难例：合法前缀、完整编码、合法动作与实际开局库推荐集合均 **32/32通过**。普通训练5521例与固定32、128开局留出之间，精确棋盘、左右镜像、旋转并交换阵营的等价轨道重合均为0；编码输入与固定32重合也为0。旧能力留出653例、普通留出353例的相应重合亦为0。

发现一项泛化验证局限：开局565训练/128留出只按左右镜像分组。左右镜像重合0，但加入180度旋转并交换双方阵营后，训练/留出共享 **19个等价轨道**，各涉及 **38例训练、38例留出**。固定32中有 **2例** 对应这些跨组等价轨道。全部轨道与具体局面列于data_audit.json。

旋转交换定义：board索引反序，对非零棋子v映射为3-v，走棋方映射为3-player；再分别做左右镜像归一。该变换保留跳棋几何与双方相对目标。网络编码仍保留原玩家身份平面，因此这不是精确张量重复，但这38个留出局面不代表严格全新等价局面。

本轮保持原固定32与原回放，使优化实验可与原控制比较。原128开局留出、653旧能力与353普通留出已被多轮查看，均作诊断，不作新冠军独立验收。后续扩大训练前，应生成全新开局分支，按完整镜像+转方轨道隔离；最终模型再用未参与选择的整局独立对战验收。

复算入口：用train_opening121.book_samples(OpeningBook())生成两组；对每个decision_id计算 min(orbit(id), orbit(rotate_swap(id)))，其中orbit为fit_opening121_hard32.orbit。两组归一键取交集即19轨道，逐例归属得到双方各38例；与原fixed32.json比对得到2例。原始源文件与数据SHA256见JSON。
