路线图第3步：固定现役v3 CNN、strict121；本次审查不训练、不晋升、不启动实战。审查对象为`az121.py`的PUCT，以及`rules121.py`和相关测试。审查时主代理正在补充时间预算和观测字段；下列结论针对保留原选择/回传逻辑的版本。

## 已确认的实现语义

| 项目 | 代码证据与判断 |
|---|---|
| 回传视角 | `expand`返回当前叶走棋方价值；回溯每层反号。选择访问过的子边用`-child.q`，转回父方视角。未发现反号错误。新观测`child_q`仍是子方视角，作图需要取反；`root_q`是根方视角。 |
| 首次访问 | 未访问边使用0（现役`fpu_mode=zero`）；可选parent使用父节点自身q。它不是将未访问节点当作已知和棋，而是首次探索基线。已有synthetic测试证明它会改变访问覆盖，不能据此直接称zero实现错误。 |
| 规则终局 | 在NN之前调用`rules121.terminal`；胜/负返回±1、和返回0。strict的P1先手/equal-turn规则保留，终局优先于历史重复与240限步。无合法动作另返回0，与`Game.result`的无合法动作和棋一致。 |
| 重复与历史 | 根传入完整Counter，每个simulation复制，走到子节点后按棋盘+下一走棋方增加计数；三次重复由规则终局处理。各simulation不相互污染原历史。根局面诊断必须从opening重放历史，不能只传board/player。 |
| 合法动作 | 仅对`get_all_moves`产生动作计算softmax。规则层按同起点终点保留一条合法路径，策略端点编码对应这一定义。P2 canonical只映射特征/动作id，返回的仍是实际棋盘路径；身份平面仍在。 |
| 缓存与转置 | 搜索没有跨局缓存或转置表；每次新建树，不会因仅board作为缓存键漏掉重复历史。代价是同一局面由不同树路径到达会重复NN评估，并且每步重新建树；这是效率特征，不是已证实的规则bug。 |
| value_scale=0 | 仅屏蔽非终局NN估值，终局±1仍有效；策略prior仍逐叶参与选择。不能称“纯策略argmax”，也不能称“完全不看价值”或随机rollout。 |
| 最终选招 | 使用根访问次数最多动作，访问数并列时按动作枚举顺序选第一个；未按q直接选招。关闭noise后没有随机打破并列。需单列visit tie，尤其低模拟量；这是确定性约定，不是当前已证实bug。 |

## 有证据的限制和待检验假设

1. **模拟量不是固定搜索深度，也不是等耗时。** 现役32指完成32次模拟；非终局根还额外做一次NN，部分模拟终局不再NN。因此`nodes`不能直接报告为NN调用数或独立棋盘数。32→128→512对比能检查增加计算后的选招变化，但不能推导同时间对C参考更强。
2. **价值分布可能影响探索覆盖，仍需数据。** zero首次访问与已访问边q共用PUCT排序；有阵营先验的value可能使探索偏向少数边。相关FPU测试只确认机制存在。真实v3是否受损、加模拟是否能纠正，要看固定根的访问覆盖、根方q与选招变化，不能把历史模型弱直接归因于此。
3. **当前回报没有显式胜局节奏项。** 真终局胜均为+1，无折扣、无own_moves优势。因此即使搜索正确发现两条胜线，也没有直接目标要求选快至少2手者。relay的tempo标签不能当作搜索必须符合的规则最优证明；point与tempo应分别报告。
4. **历史输入只有局部摘要进入CNN。** 网络六平面包括当前根重复次数，完整过去局面Counter只由搜索规则使用。相同当前编码不保证未来重复风险相同；搜索仍使用完整Counter裁终局，未发现把完整规则历史丢弃。这个表示局限不是当前规则执行bug。
5. **时间预算是软截止。** 主代理新增`time_limit`在simulation之间检查，且至少完成一次；根展开及一次展开可能超时。等时间实战应记录每手实际elapsed、实际模拟量、超限幅度、整局总耗时，并给C引擎同样明确的截止/完整深度处理语义。不能只凭同一个名义秒数宣称严格等算力。
6. 搜索使用Python合法动作/规则和逐叶单样本CNN调用；C参考使用原生搜索。时间比较应固定机器、线程数、并行负载、预热、开局和配置，保存实耗；不为提高某方结果额外给它书库、根安全筛选或启发混合。现役`root_safety=False, heuristic_mix=0, fpu_mode=zero, policy_temperature=1, noise=False`应冻结。

## 本轮诊断解释边界

48个relay根已被诊断使用，11个稳定偏好根只是两套固定续弈下rear/front比较；不是全新独立验收。纯策略与32/128/512、value_scale1/0可以比较实际合法argmax、pair内访问分配和选择稳定性。仅当最终动作确实选中pair之一时，才能引用该动作的归档真实收益；候选外动作只记“未标注”，不可贴错招/收益0标签，也不可将候选外视作已证明更差。

如果尚未启动固定实战，只报告局面诊断；即使局部命中增加，也不称棋力升级。固定同时间实战须另冻结协议并交换引擎位置，保持P1先手语义，完整记录胜负/真和/截断与终局原因。
