# 第3步双头价值训练：固定评测协议

## 用途和边界

本轮比较只优化价值头与联合CNN训练。数据来自已冻结的真实终局试验；训练16开局组，开发8开局组。开发只作固定预算研究判断，不能用来证明独立棋力提升。没有整局竞技结果时，不晋升冠军。

开发组不参与采样、损失或先验估计。原v3基线评一次；两组固定2000次更新的最终检查点评一次。每400次的训练曲线只使用训练池，不挑开发最优检查点。中途模型保存不改变固定终点原则。

## 两组训练范围

- head_only：只优化`value.*`，其他参数与缓冲区必须逐字节保持；目标为真实价值MSE。
- joint：全部网络参数可优化，真实价值MSE + 0.25独立归一策略CE + 0.1旧普通训练池合法动作KL。
- 每步价值16例（8个末16手、8个全程），策略16例，先按训练开局组等概率抽组再组内抽样。两池分别应用原始mask，再把另一头权重置零；同一个样本可独立出现在不同池，不假装成独立新样本。
- 相同v3、2000更新、学习率1e-4、AdamW、权重衰减1e-4、梯度裁剪1；两组采样序列逐步核对并保存哈希。两组目标与可更新参数范围不同，不称为只改一个参数的实验。

## 主价值指标

主指标是开发8开局组等权的group macro MSE。先对每组中**所有有效价值样本**计算点均MSE，再对组均值等权平均。不先把组内每盘棋等权平均，这一层次在实验前固定。

同时报告全部样本点均MSE、逐组和逐盘记录，避免一盘长棋凭点数独占主指标。按P1/P2分层时，也先在每组内对该方样本求均值，再等权平均有该方样本的组。

`value_weight<=0`的样本不进入价值指标或先验估计。末16手取`terminal_distance<=16`，与整个样本池使用相同的目标定义。

辅助报告符号准确率、Pearson相关性、预测均值/标准差及目标均值/标准差。预测或目标方差为零时相关性记null，不填成0或1。符号使用严格`sign`比较，预测0不被算作±1的正确符号。

## 两个简单基线

1. 常数零：每个目标的平方误差为z²，再按相同点/组规则汇总。
2. 训练走棋方先验：只用训练有效价值池，分别求P1和P2目标的点均值，开发每个样本按走棋方套用该均值。整个开发与末16手共享这同一组训练先验，不再按开发或阶段重新拟合。

训练先验不使用开发胜者比例。开发自然出现的先后手胜负分布偏移保留原样，不删除不利棋谱、不重标结果、不按胜者重采样开发。若价值头学到训练胜率捷径而在开发失效，应如实报告这种压力诊断结果。

## 预声明门槛

每组候选必须同时满足：

- 全开发group macro MSE比原v3至少减少0.05。
- 全开发group macro MSE严格低于常数零和训练分方先验。
- 末16手P1与P2各自group macro MSE均不劣原v3，允许1e-8数值误差；双方子集均须非空。
- 合计末16手group macro MSE严格低于常数零和同一训练分方先验。
- 旧能力策略CE、旧能力价值MSE、普通留出策略CE分别不超过原v3对应值+0.05。
- 新开发策略CE不超过原v3对应值+0.05。
- head_only额外要求非价值完整state哈希不变，且相同新开发策略输入的合法动作logits逐字节哈希不变。该检查不只比较argmax或策略准确率。

比较门槛使用未四舍五入的数值。不因接近门槛临时放宽，不在本开发上补训或改学习率重考。

两组都通过时，以最终全开发group macro MSE较低者选一次；差不超过1e-6优先head_only。只有一组通过则选该组；都失败则selected=null。选择只意味着可准备步骤4，绝不直接登记冠军或替换GUI。

## 如何解释结果

价值训练误差下降表示拟合；group macro开发误差改善表示在这8个开发组上的终局目标预测改善。两者都不能直接换算为胜率。即使价值指标通过，也需要步骤4把固定候选放进搜索并以新的独立开局做整局确认。

8个开发组数量有限，P1/P2与同组棋谱互相关联。报告应保留逐组结果、双方与末16手分层，不能把所有位置点数当作独立比赛数，不能从符号准确率得到棋力胜率。

主评测函数在`value121_metrics.py`，门槛由`gate(candidate,before)`实现；trainer再合并新策略保护和head_only逐值保持，最终固定规则选择。此次协议复核只读trainer源代码，未读取或选择新模型。
