## 门槛与保护审查

逐项重算和原始checks一致：两组的开发提升0.05、优于零值、末16手双方不劣v3、末16手优于零值均失败；优于训练先验通过；旧策略CE/旧价值MSE/普通CE以及新策略CE保护通过。

原运行的head_only合法logits字节哈希检查为false，本审计保留原工程门槛失败，不擅自改结果。训练实现审查已用独立合成复现定位到评测时requires_grad状态不同引起的微小CPU数值差异；在统一状态后logits可逐值一致。因此该失败不应表述为策略参数被训练改写。主线程对后续评测函数进行了运行后修复，原源码快照与原结果不覆盖。本审计未重新评估新开发模型来替换旧哈希。

## 下一步建议

结束当前两个配方，不在这8组开发上补训练或调学习率重考。先从已保存数据检查按组/走棋方/末16手/根进度分层的胜负分布及实际采样目标，明确哪些棋形能区分真实输赢、哪些只提供阵营先验。

随后若收集新训练数据，应在真实终局约束下增加训练中缺少的“同一走棋方、不同胜负、相似进度”覆盖；不根据开发胜者比例重采样或伪造胜负标签。重新设计的训练需要新的开发隔离，不把当前8组换个名字继续当未见样本。

8个开发组足以否决当前配方，但不是独立整局胜率验收。当前冠军保持v3，下一步仍是数据与价值学习诊断，而非扩大搜索模拟数。
