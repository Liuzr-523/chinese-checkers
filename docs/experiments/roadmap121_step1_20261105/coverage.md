# 【路线图第1步】数据覆盖与监督多样性诊断

## 结论

开局训练的565条记录只覆盖234个完整对称轨道；后段第7—10步P1有160条、P2有188条，分别只有80与94个完整轨道。普通回放虽有5521条记录，后段来自原教师的双方各148条只有各106个精确棋盘，普通新增部分双方各48条。问题不是完全没有后段数据，而是有限分支、重复监督与训练目标共用参数。

开局root全部value_weight=0，565条库招不提供终局价值监督。原教师回放有86个同棋盘＋走棋方出现不同真实终局z的分组；这些是结果多样性，不直接认定为污染。

完整分组的decision_id、记录数、推荐集合数、有效z列表与出现的ply保存在coverage.json。精确分组仅按board:player，不包含ply和重复次数；不同ply/repetition可能仍是不同完整网络输入。

相同局面在不同完整棋局中可能出现不同合法着法、不同终局结果；价值学习应估计条件期望，而不是要求每次胜负相同。本表揭示监督分布与优化张力，不将28个不同策略分组或86个不同z分组直接判为脏数据。若要进一步判污染，应追查原棋谱、实际规则及终局验证，而不是抹去失败样本。

## 第7—10步重点

原教师训练双方各148条，均各106个精确局面，胜负标签近似平衡。普通训练双方各48条，P1有效z为胜28/负12/和8；P2为胜12/负28/和8。这种阵营差异来自已有完整对局的结果分布，应在扩大数据时监测，避免把单一对手或起始阵营优势学成局面价值。

开局库训练后段P2比P1多28条；565库招经左右镜像和转方归一后仅234轨道。继续复制这批样本会增加暴露次数，但不会增加独立局面覆盖。后续应按全新分支/完整对称轨道扩展，并分别统计双方阶段，而不是只报总样本数。

## 可复算方式与范围

运行：`python diagnostics/diagnose121_coverage.py --output <JSON路径>`。默认从fresh121_projection_20261105/data_sources经cap_opening121_replay.load_data重建旧/普通train与validation；保留既有开局128精确输入去重规则，未改原划分。

按已知canonical编码恢复player：plane3为原P1身份；plane4×240四舍五入恢复ply；己方步数floor(ply/2)+1。阶段为1—3、4—6、7—10、11—20、21—40、41及以后。输入ply通道上限240不影响末阶段归类。完整轨道归一包含左右镜像与180度旋转换色。

load_data对原教师/普通对局执行现有终局与合法棋谱校验；只统计value_weight>0的真实结果。该程序没有模型推理、教师查询、训练或新对局。输入数据与相关实现SHA256保存在JSON。3项单元测试通过，覆盖阶段边界、P2/ply恢复、无价值root不伪造和棋、相同棋盘不同终局的保留统计。

### 需要优先处理的分布问题

普通回放按原始阵营分开后，训练与验证的胜率标签分布相反：P1训练有胜负样本胜率71.5%，验证23.7%；P2训练29.0%，验证76.7%。网络保留原玩家身份plane3，因此可以利用阵营捷径降低训练误差，却在验证分布反转时失败。此结果应与价值代理对实际预测的阵营依赖/相关性诊断合并判断，不能只看总体正负近似平衡。

原old_teacher管道还丢弃了真实和棋：训练56局中7盘equal_turn_goal_draw（671个续弈路径），验证8局中1盘（87个路径）均被samples_from_game直接排除。这与normal管道保留2盘真和棋的182个weight1标签不同。两类监督来源的终局分布不一致，应在后续数据设计中统一真实和棋处理；本轮只记录问题，未改训练代码或重训。
